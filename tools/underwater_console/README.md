# Underwater USB 控制台

Python + Tkinter/ttk 上位机，调用本分支真实 `pyflorid.UnderwaterTeleop` API。
搜索和选择 USB Bulk 设备、连接、使能（Gravity）、失能（Damp）、进入遥操，
并显示设备返回的模式、两臂电机位图、过渡进度、Busy / 拒绝原因。
固件升级页可选本地文件，显示传输进度，写入后重启并查询启动状态。
设备设置页可读取、修改和保存遥操、重力、摩擦与力反馈参数。
机械臂控制页提供十轴 MIT 滑条，并通过 USB Bulk 以 250 Hz 发送控制命令。

## 启动

先在本 worktree 构建 Python SDK：

```sh
cmake -S . -B build-underwater-sdk -DCMAKE_BUILD_TYPE=Release -DBUILD_PYFLORID=ON -DBUILD_TESTS=ON
cmake --build build-underwater-sdk -j 6
python3 tools/underwater_console/run.py
```

`run.py` 优先加载本 worktree 的 `build-underwater-sdk/pyflorid` 扩展，避免调用原
libflorid 中没有 Underwater API 的版本。使用其他构建目录或已安装的本分支 wheel
时，设置相应 `PYTHONPATH` 即可。运行需要 Tk，Linux 发行版中通常是 `python-tk`
或 `python3-tk` 软件包；没有额外 GUI 库依赖。

默认产品名为 **Underwater**，下拉列表同时显示设备序列号或精确 URI。
搜索只枚举 USB，不打开其他设备探测；选好后点击连接。生产固件使用 Vendor
Bulk，不能把 UART 日志串口当作此界面的 RPC 连接。

## 使用

- 「失能」请求 Damp，「拖动」请求 Gravity，「跟随」请求原 Retract → Teleop 流程，「上位机控制」请求 Control。
  界面显示实际固件模式：请求已处理不代表已完成使能或对齐。
- 状态每秒刷新；失败后保留上次数据显示并明确标注读取失败。
- 连接、断开、模式命令使用单 worker 按提交顺序执行。升级、进度、取消在
  独立后台线程执行；升级期间仍可提交模式 RPC，Busy 与原因由固件返回。
- 断开连接或退出程序只关闭 SDK，不自动发 Disable。Gravity / Teleop 保持当前模式；
  v0.11.0 的 Control 会因断连或命令超时失能。需要主动失能时点击“失能”。
- 所有响应保留业务状态和 reason；超时不表示远端请求已撤销，应查询实际状态。

## 十轴 MIT 控制

需要支持 v0.11.0 ArmCommand / ArmStatus 的固件。控制页按主臂、从臂分成两组，每组依次为 joint1～4 和夹爪，共十行。角度与参数使用**电机坐标**，不额外套用 Teleop 的主从比例或方向映射。

1. 连接设备。每轴首次收到新鲜反馈后，页面用实测角度初始化目标角度；手动编辑过的目标保留。
2. 设置目标角度、速度、前馈力矩、Kp 和 Kd。默认速度和前馈力矩为 0，Kp 为 20 N·m/rad，Kd 为 0.5 N·m·s/rad。需要同步到当前姿态时，点击「读取当前角度」。
3. 点击「上位机控制」。RPC 成功后，后台线程每 4 ms 发送一份十轴命令。拖动滑条立即更新目标；输入框按 Enter 或移开焦点后应用。
4. 点击「失能」「拖动」或「跟随」可直接请求对应模式。设备接受切换后停止发送 MIT 命令；请求失败时显示固件返回原因。

默认勾选「重力补偿（MitWithGravity）」，固件在输入的前馈力矩上叠加当前姿态的重力补偿，夹爪的重力项为 0。取消勾选后发送纯 MIT。开关可在 Control 中实时调整。本页参数只用于当前控制命令，不写入 DeviceSettings 或 NVS，也不改变跟随模式的调参值。

| 两臂电机 | 滑条范围 / rad | 来源 |
| --- | --- | --- |
| joint1、joint4 | −6.28～6.28 | 两臂 URDF limit |
| joint2、joint3 | −2.2～2.2 | 两臂 URDF limit |
| 夹爪 | −3.14～3.14 | 用户指定；URDF 不含夹爪 |

主臂 URDF limit 已按从臂同步。控制台随附 `underwater_console/joint_limits.json`，无需运行时访问固件仓库。修改 URDF 后，在 SDK 仓库重新导出：

```sh
python3 tools/underwater_console/sync_joint_limits.py \
  ../Ragtime_Firmwares/firmware/apps/underwater_teleop/models
```

输入错误会标红并显示该项未应用及当前值，不静默截断。增益遵循现有 SDK 的非负要求，角度输入遵循表中滑条范围。「失能」不受输入框内容影响。实测角度超出滑条范围时保留测量值并提示，不自动发送范围端点作为新目标。

界面每 50 ms 更新最新状态，显示实际模式、观察到的发送／接收频率、在线与执行位图，以及固件命令拒绝／退出原因。实测角度后的 `*` 表示反馈不新鲜。250 Hz 是发送目标频率，普通桌面系统的线程调度会产生抖动；设备沿用已有 Control 超时和断连处理。窗口缩小时，电机表可滚动。

## 设置零点

先点击“失能 · Damp”，并在失能状态下摆好主臂、从臂的零点姿态。
读取到 Damp 且没有升级正在进行时，“设置零点”按钮才可点击；点击时还会重新查询状态。
操作将两路全部已配置电机（包括夹爪）的**当前位置写为新零点**，不会规划运动回旧零点。
期间蓝灯闪烁，电机保持失能。界面等待校准结果，成功／失败和缺失电机位图显示在日志中。
离线电机也计入反馈等待，初次发送加最多三次重试；结束后仍为 Damp。

## 设备设置

连接后自动读取设备设置。页面按遥操映射、重力、主臂摩擦、从臂摩擦、力反馈
分组，包含 110 个数值以及“电机掉线蜂鸣报警”开关；表格列对应 joint1～4 和夹爪，重力只有四轴。
蜂鸣报警默认开启，取消勾选并“应用并保存”后停止鸣响，重启后仍保留设置；掉线日志继续输出。
可编辑的字段和单位见 [SDK 设置接口](../../docs/underwater.md#device-settings)。
比例保留有符号数值，界面不静默截断；空值、非数字或非有限数值会明确指出字段。
对齐轨迹、零点/轴方向以及已辨识自负载系数保留在固件中。

“恢复默认到表格”读取固件编译默认值，只回填页面。“应用并保存”才会弹窗确认：
即将让两臂进入 Damp 并失能。取消不发送任何失能或设置请求。
确认后只等待本次写入前在线的电机：Damp、没有使能中的臂、每个对应电机都有
新鲜的明确失能反馈，再提交一次设置并保存到 NVS。原本离线的电机不阻塞。
等待最多 5 秒，每秒显示缺失位图和原因；失败、超时或状态读取失败都不写设置，
不会自动重试。保存后保持 Damp，由用户手动重新启动。

返回值显示 revision、source、storage_error 与设备原因。source=Corrupt 或
StorageError 时，设备仍可返回当前可用的编译默认参数，页面照常显示和编辑。
写入被 Busy 或存储错误拒绝时保留用户编辑值，并显示实际设备版本和原因。
SDK 本身不强制失能或设置模式门槛，这个确认流程只在上位机中执行。

## 固件升级

选择匹配开发板和启动布局的 `zephyr.signed.bin`。界面自动读取 MCUboot
二进制头中的 `MAJOR.MINOR.PATCH+BUILD`，无需填写验证版本。上传时重新从实际
发送的文件内容读取版本，因此重新编译、覆盖所选文件后也会使用新版本信息。
默认勾选“写入后重启”，同版本重新编译的固件也可直接升级。
100% 表示文件写入完成；重启响应的“请求已接受”和“USB 离开”独立显示。
重连后自动查询运行版本和启动槽，并显示运行版本是否与固件的
`MAJOR.MINOR.PATCH` 一致；也可点击“查询启动状态”重新读取。
FCI 当前不返回 BUILD 或运行镜像 hash，版本一致不能区分同版本的不同构建。
未读到 MCUboot 版本信息会在界面显示，不额外阻止上传；镜像仍由设备处理。

写入和重启使用已确认的固件时序：先进入 Damp，确认请求时在线电机的新失能
反馈，再写 Flash / 重启。超时会返回失败，升级后保留 Damp，由用户重新启动。
界面不会自动反复重发升级或重启，也不安装 MCUboot bootloader。

USB 调用和文件读取在线程池中执行；进度、状态和日志由 Tk 主线程更新。
关闭连接会等待正在使用同一 SDK 对象的调用结束，防止并发销毁连接。

## 检查

```sh
python3 -m unittest discover -s tools/underwater_console/tests -v
python3 tools/underwater_console/run.py --smoke
```

`--smoke` 只创建窗口然后退出，不扫描或连接 USB。后台控制测试使用 SDK mock，
验证二进制版本读取、同版本升级、Busy 显示路径、命令顺序、异步重启和断开不失能。
设置测试覆盖 110 个表格值、取消确认、失能等待/超时、原离线电机、设备存储错误，
以及成功/失败时的表单显示行为。
真实协议帧与 bulk CRC 路径由 C++ `test_underwater_teleop` 回归测试覆盖。
控制页测试还覆盖十轴顺序、MIT 类型切换、限位、输入应用、四个模式按钮和旧反馈隔离。后台测试验证 RPC 完成前不发送、切换成功后停发、Busy 不擅自停发，以及断开连接时等待线程退出。Tk 控件测试需要图形环境；无显示服务时会明确跳过。
